# 怎么写角色档案

> 场景那份在 `how-to-write.md`，角色外观那份在 `how-to-write-character.md`，
> 道具那份在 `how-to-write-prop.md`。
>
> ★ **这一份跟那三份不是同一种东西，别套那三份的纪律。** 那三份写的是**出图资产**，
> 每一句都要喂给图像模型，所以有"300 字上限""每格单独读懂""不写性格"这些规矩。
> 角色档案**不出图、也不进图像提示词** —— 它是表演与声音的底本，
> 下游每场戏改写之后才进提示词。下面第零节先讲清这个分界，不看这一节容易两边串。

---

## 零、★ 先搞清这一层在哪儿 —— 官方把角色拆成四种生命周期，我们补第五种

从 Cinema Studio 3.5 项目书 + `ACTING SKILL.md` 逆推出来的，这是理解本篇的前提：

| # | 是什么 | 生命周期 | 落在哪 |
|---|---|---|---|
| ① | **外观 descriptor** | 写一次、**逐字复制**进每条提示词 | `characters[]` + `outfits[]` |
| ② | **Voice prompt** | 写一次、**原样贴**进 audio 字段 | `bios[].voice` |
| ③ | **acting master profile** | 写一次、**每场改写、核不动** | `bios[]` 八块 |
| ④ | 每个镜头的表演块 | 下游**每镜现写** | 不是我们的活 |
| **⑤** | **阶段状态** | **剧本里发生了什么事 → 他因此成了什么样** | **`bios[].arc[]`** |

**③ 为什么必须是静态资产、不能每次现推：**
没有它，下游每个镜头把"焦虑"各自翻成一串动作 —— 这次翻成看手表、下次翻成搓裤缝、
再下次咬指甲。三次之间**没有任何东西保证这是同一个人的习惯**。

那就是 character drift 在**行为层**的翻版，跟「每份服装各写一遍脸」是同一个病。
官方的原话是：

> That paragraph is **the source of truth**: each scene adapts it to the moment's
> posture and action, but **the core never changes**.

**④ 为什么不归我们：** 场次级的五支柱（目标 / 阻碍与代价 / 战术 / 节拍 / 潜台词）
是"这一场他要什么"，只有 super-objective 是全片级的。我们只出那一个。

### ★★ ⑤ 官方没有这一层，为什么必须补

上面那句 `the core never changes` 加上 §8.2 的 `Never contradict the master`，
合起来暗含一个假设：**一份档案全片有效**。官方压根没设计"一份档案里装着好几个时期、
执行时自己判断该用哪一段"这件事。

于是**有弧光的角色会出事**：一个人开篇活泼开朗、后半段变得沉默，这个转变要靠表演演出来；
而档案里只写了「活泼开朗」，下游手上只有这一张卡 —— 它没有任何依据知道该往沉默演，
`Never contradict the master` 还会主动把它按回开朗。它只会一路照开朗演到底。

**这跟 Lira 那个洞是同一种洞**：官方把"每场改写"这把锁造得极好，
**却没人负责告诉它"现在改写的是哪个时期的他"。那个人还是你。**

### ★ 这一层只能补到「事实」为止 —— 这是本篇最要紧的一条分工

| 是什么 | 归谁 | 为什么 |
|---|---|---|
| 剧本里发生了什么事、他因此成了什么样 | ✅ **我们**（`arc[]`）| **事实**。谁去查都是这个答案，不需要眼光，只需要仔细 |
| **从第几场起，让观众看见他变了** | ❌ **导演** | **节奏判断**。同一件事，导演可以让观众提前预感到，也可以突然给一记重锤 —— 两个导演给出的答案不一样 |
| 这一个镜头此刻的表情姿势 | ❌ 下游 | 每镜现写 |

写进去了，导演就没得选了。所以 `build.mjs` 有 `ARC_SCHEDULE` 那道闸门专门拦它。

### ★ 因此八块是「开场状态」，不是「全片恒定」

这一条是改过来的 —— 早前这份文档和 `SKILL.md` 都写着"档案是全片恒定的底本"，
**那句话对有弧光的角色是假的**。

**为什么不能只把"变的部分"锁在少数几个字段上：** 曾经想过"声音、步态、习惯动作锁死不变，
只让心理引擎跟着变"。站不住 —— 那是把**硬件**和**软件**搞混了。
缺一条胳膊、脸上有块疤是硬件（在底档里，本来就不变）；
而声音、习惯动作、走路样子**全都是"这个人现在心里什么状态"的外在表现**，是软件。
经历真的把人压垮了，这些全都有权跟着变，甚至可能**长出一个原来没有的新习惯动作**
（创伤之后新添的那种）。

所以真正永不变的只有两样：**身体本身的事实**（在底档里）、
**他身上发生过的那件事**（过去时，已经发生完了 —— 这就是 `posture` 里那个"来历"）。

★ **没有弧光的角色 `arc` 留空，开场状态就等于全片状态** —— 这条路径**合法，不是缺项**。
功能性角色（喜剧配角、只推剧情的那种）本来就不该有弧光，别硬给他铺三个阶段。

## 一、★ 双向墙 —— 这个模块跟本 skill 最贵的一条纪律正面冲突

`how-to-write-character.md` 第六节写着「角色专有三条不写：表情情绪 / 姿势动作 / **性格评语**」，
而这份档案要写的恰恰就是性格。**两条规矩都对，但必须各管一边，两个方向都有闸门：**

| 方向 | 禁什么 | 违反的后果 |
|---|---|---|
| `bios[]` → | 禁**服装与相貌**词 | 档案退化成外观复述，白建一层 |
| `characters[]` / `outfits[]` → | 禁**性格与表情**词（`EMOTION` / `TRAIT` 一个字不改，**不给豁免**） | 性格回流进 brief，出图又拿一个瞬间当全片的形象基准 |

服装那半是官方原话，不是我们的洁癖：

> **No wardrobe.** Clothing and costume live in the scene/look block of the prompt,
> never in the acting profile. **The profile must survive any costume change.**

判据一句话：**换了衣服，这份档案还成立吗？** 不成立就写错了。
一个例子：「紧张时把领口扣到最上一颗」—— 听着很具体，但他光着膀子那场怎么办？
改成不依赖衣服的写法（「紧张时手会去够颈侧」）。

相貌那半的理由是**不重复**：脸、体格、发质在底档里有唯一权威版本，
在档案里重写一遍就是两个版本的脸 —— 那正是要防的漂移。

## 一之二、★ 第二道墙：时间墙 —— 加了 `arc[]` 之后才有的

第一道墙分的是"哪一层写什么"（性格 vs 外观）。这一道分的是"**哪个时期**写在哪儿"，
同样**两个方向都有闸门**：

| 方向 | 禁什么 | 违反的后果 |
|---|---|---|
| 八块 → | 禁**跨时期词**（`后来 / 后期 / 渐渐 / 越来越 / 最终 / 一路`）| 两个时期挤在一格里，下游不知道现在该演哪个 |
| `arc[]` → | 禁**场次分配句**（`从第 N 场起 / 后半段 / 之后每场`）| 替导演把节奏决定做了，导演就没得选了 |

判据一句话（跟「换了衣服这份档案还成立吗」同一个用法）：

> **这句话是剧本里发生过的事，还是我替导演决定的节奏？**

```
✗ 八块里写：「两肩往前收着，后来越来越塌」
✓ 八块只留「两肩往前收着」，把「肩塌得更低」挪进 arc[].state

✗ arc 里写：「从第 60 场起都按这个演」
✓ arc 里写：「儿子被带走那天之后」—— 说事件，不说从哪一场开始生效
```

★ **一条重要的例外：`posture` 里的「来历」不受这道墙约束。**
「两肩往前收着 —— 早年扛货落下的」是**前史、过去时**，故事开始之前就发生完了，
往后怎么演它都不会变。官方 rule 8 `Physique carries biography` 明确要求写它。
所以 `BIO_DRIFT` 词表**刻意不收**「当年 / 早年 / 从前 / 落下的」。

★ **那件事发生在哪一场是事实，可以写** —— 但写进 `arc[].scene` 那个专门的字段，
不要写进散文里。区别很实：
「这件事发生在 S05」是定位（副导演的活，闸门还会去场景表核对它存不存在）；
「从 S05 起按这个状态演」是分配（导演的活）。

## 二、八块 = **开场状态**，块序是官方定的

ACTING §6 原文 `block order is fixed`。这不是排版偏好，**别重排** ——
外壳渲染卡片、`build.mjs` 拼装成品底本都按这个顺序走。

★ **这八块写的是「他第一次出场那会儿是什么样」**，不是全片平均值，也不是"恒定不变的部分"。
后来变了什么写在 `arc[]`（见第四之二节）。自查一句：
**这是他第一次出现时的样子，还是我把几个时期揉成了一个平均值？**

### 1. `posture` 体态与来历

年龄和体格由**底档**承担（拼装时自动落到这一块前面），这一格只补两样：
**体态**，以及**这个体态是怎么来的**。

官方 rule 8 的说法是 `Physique carries biography` —— 身体是一份文件，
职业、旧伤、自我认知要能从它上面读出来：

> ✗ 结实，肩宽　　←　这是底档已经写过的体格
> ✓ 两肩常年往前收着，站定时重心压在整只脚上，很少换脚 —— 库区扛货落下的

### 2. `engine` 心理引擎

一句话。它要能**解释上一块那个体态是怎么长出来的**，两块之间有因果才算写对。

> ✓ 他认定「先扛住，人家才看得见你」，从不先喊累

### 3. `vocalProfile` 说话在戏里怎么变

跟 `voice` 分工不同，别混：

- `voice`（第 ⑨ 项）锁 **声音本身长什么样** —— 原样贴 audio 字段，不按场次动
  （真的随弧光变了，在阶段里另给一版，见三节末）
- `vocalProfile` 写 **它在戏里怎么动** —— 速度往哪边移、什么时候破音、越急是越快还是越慢

官方要求两者 `Both must agree with each other`。写完对一遍：
`voice.manner` 说"越急越轻"，这一格就不能写"急起来会喊"。

### 4. `tics` 习惯动作 —— ★ 每一条都要带触发条件

写四样：**招牌小动作 / 压力下的小动作 / 掩饰行为**（他做什么来藏住感受）/
**那张脸的面具**（默认表情，以及它掩盖着什么）。

官方 rule 2 是这份档案里最容易漏的一条：

> **Tics without triggers are decoration; tics with triggers are dramaturgy.**

格式是 `[什么动作] + [什么时候 / 为什么做]`：

> ✗ 他会转手里的硬币
> 　　—— 装饰。下游不知道什么时候该让他转，于是每个镜头自己决定，三镜三个样
> ✓ 掂量一件事的时候，那枚旧硬币在指节上来回走
> 　　—— 有条件。下游每场都对得上，而且"硬币停住"立刻就成了一个可用的重音

`build.mjs` 有一张触发词表兜底（`BIO_TRIGGER`），但它只认得几个常见说法 ——
**没报错不等于每一条都带了触发条件**，写完自己数一遍。

### 5. `gait` 步态 —— ★ 必须取名

官方 rule 3：`A memorable coined name inside quotes anchors the biomechanics`。
先起一个引号包住的自造名，再拆开重量 / 步幅 / 躯干手臂 / 头怎么动：

> ✗ 走得慢，脚步沉
> ✓ 一种「扛货的走法」：步子短，落脚先着外侧，肩膀不摆，两手垂在身侧微微离身，走多远都这个速度

**取名不是修辞。** 它把一串生物力学描述压成一个可复用的把手 ——
下游每场改写时照这个名字对齐，比每次重读一段描述稳得多。

★ **不会走路的角色，这一块要做转移适配，不是删掉。** 轮椅角色写"轮椅操控风格"，
一样取名、一样绑定触发条件（"急起来推得又快又碎，撞门框也不减速"）。
这跟下面第七节那条「转移不删除」是同一条规则。

### 6. `crack` 面具裂开的条件 —— ★ 至少一条，必填

官方 rule 4：`Every profile carries at least one "However, when X — ..." clause.`
先有面具（第 4 块的最后一样），再有让它塌掉的**精确条件**：

> ✗ 偶尔会露出真情绪
> 　　—— 没有条件，等于没有
> ✓ 有人提到他弟弟，那张平脸半秒就散了：喉结先动一下，眼睛往地上找，答话又快又碎
> 　　—— 随即察觉，把手插回口袋，重新抹平

官方把这条叫 profile 里最有电影感的装置，理由在表演量表的顶格：
**一个人同时演两个真相**，是活人跟木偶的分界（`the two-truths rule`）。

### 7. `softeningTarget` 唯一软下来的那个 —— 可选，但**只能一个**

官方 rule 5 原话就是 `One — not two.` 给两个就稀释了，不给不算漏项。

> ✓ 库区那只跛脚的黄狗 —— 只对着它，脸是真松下来的

### 8. `eyeLife` 眼睛怎么活 —— 必填

ACTING §7 原文是 `mandatory in every profile`，而且官方把 **dead eyes 列为
AI 表演的头号破功点**（坏表演图谱第 15 条）。四样：

1. **扫视与注视目标** —— 眼珠一直在动，会飘、会滑到一处细节再回来，从不锁死在一点
2. **眨眼的频率与质量，且跟状态绑** —— 紧张时成串快眨；控场时慢而有意；抽离时眨完发直
3. **眼里要有光**（catchlight）—— 项目书专门讲过：连深色眼睛也要有一点反光，没有就是死人脸
4. ★ **眼睛先于头到位** —— `Eyes lead the thought`，眼睛先找到目标，头才跟着转

★ **刻意的静止不等于死。** 如果这个人的基调是近乎不眨眼的沉静，
就写"眨眼少、慢、是有意的"，并且让目光仍然缓慢地有目的地移动 ——
官方的说法是 `a decision, not a freeze`。

## 三、`voice` —— 四要素，拆成四个字段

项目书点名要在前期锁的就是这四件：**音区 / 速度 / 口音 / 腔调**。

| 字段 | 写什么 |
|---|---|
| `register` | 音区与音色 —— 低/高、厚/薄、哑/亮、胸腔还是鼻腔 |
| `tempo` | 速度与停顿 —— 快慢、句子长短、句间留多久 |
| `accent` | 口音与出身 —— 哪儿的口音、有什么习惯尾音 |
| `manner` | 腔调，**以及压力下怎么变** |

★ **为什么拆成四个字段而不是写成一句话**：为了让"四要素齐"这条闸门查得动。
一整句话只能靠词表猜，而词表在这里必然是假绿 —— 缺一件也照样过。
四个字段一目了然，缺哪件报哪件。

★ **三条纪律，跟外观资产完全不同，交付时要跟下游讲清**：

1. **原样贴进 audio 字段** —— 不改写、不精简
2. **每次说话都贴** —— 模型没有记忆，贴一次不管全片
3. **不按场次改** —— 表演每场改写，声音不跟着场次动。
   项目书那句 `The voice is not an asset` 说的是它不需要图，不是说它不用锁；
   紧接着的原文是 `Lock every hero's voice in pre-production, before the dialogues`

声音也要像外观一样做**漂移压力测试**：几次生成之间音色变了，回来把措辞锁得更硬。

### ★ 但声音真的会随弧光变 —— 这时候在阶段里另给一版

第 3 条说的是"不按**场次**改"，不是"永远不会变"。一个人经历重大打击之后，
声音真的会从又高又快变成又低又慢 —— 这不是漂移，这是弧光。

**官方那套系统处理不了这件事**：它只有一个声音格子，压根没设计声音会变。
所以做法是：`arc[]` 里那个阶段**另给一整套四要素**，
而**"这场戏该贴哪一版"由导演判断，不能让下游自己挑**（它没有依据挑）。
页面按阶段各给一个「复制声音」，就是为了让这个选择变成点一下按钮，而不是临场改写。

★ **`accent` 原则上不该变** —— 口音是出身，出身不会因为受了打击而改变。
变的通常是 `register`（压低）、`tempo`（变慢）、`manner`（不再往轻里收）。
真要动 `accent`，先问一句剧本里是不是真的换了地方生活很多年。

★ **不给阶段声音也完全正常** —— 声音没变就别写，页面会自动沿用开场那一版
（按钮上写着这一版属于哪个阶段）。

★ **复制出来的文本里只有那四句本身，不夹任何用法说明。**
早前它尾巴上带着「原样贴进 audio 字段，每次说话都贴。这是开场那一版。」——
那是**给人看的**话，而 payload 是要喂给下游模型的，混在里面会干扰它对内容的理解。
同理，「复制档案」的尾巴上早前也带着「每场戏把上面这些改写进当场的姿态与动作，
核不动；物理上做不到的行为要转移不要删」，同样已经去掉。
**这三条交付纪律只进第 9 步的汇报**（见第七节）—— 那是跟人交接的地方。

## 四、canon 两块 —— 不进那段底本

这两块不喂提示词，是给下游推每场目标用的依据。

### `superObjective` 贯穿全片想要什么 —— 必填

ACTING §2.1：

> Behind the scene objective sits a super-objective — what the character wants
> **across the whole story**; every scene objective is a step toward it.

写成**朝着某个人的动词**，不写状态 —— 状态演不出来（这是 §2.1 的硬规定）：

> ✗ 想被认可　　←　状态
> ✓ 让厂里那些老师傅承认他不是只会出力的

没有它，下游每场的目标各自成立、连不成一条线。

### ~~`degradation` 磨损弧线~~ → 已被 `arc[]` 取代，见第四之二节

★ **这是被扩展了，不是被砍了。** 原来那个字段的依据是 ACTING §11
`Degradation accumulates`（全片被磨损的角色，身体要**累积**着带，绝不在场次之间重置），
但它有三个问题：**只有"变差"一个方向**、**只是一句话**、
而"绝不重置"这条只能靠那句话提醒、没有任何机制保证。

`arc[]` 三个方向都装得下（变差 / 变好 / 新长出来的），
而且**累积语义由结构本身保证** —— 页面按阶段复制时是顺序累积的
（第二个阶段 = 八块 + 段一 + 段二），不需要谁去记得"别重置"。

## 四之二、★ `arc[]` 后来变了什么 —— 可选

一段一个阶段，按剧本时间从早到晚排。每段四样：

| 字段 | 必填 | 写什么 |
|---|---|---|
| `after` | ✓ | 触发这个阶段的**那件事**：「儿子被带走那天之后」 |
| `scene` | 可选 | 那件事**发生**在哪一场（`build.mjs` 会去场景表核对它存不存在）|
| `state` | ✓ | 一段话，**只写这个阶段变了什么** |
| `voice` | 可选 | 声音真的变了才给，四要素照样要齐（见三节末） |

### 四条纪律

**1. 锚事件，不锚场次。**
弧光是被事件推动的。「儿子被带走之后」剪辑怎么调序都成立；
「第 47 场之后」一调序就失效了 —— 场次是**制作索引**，不是戏剧索引。

**2. 只写变了的，没变的不重写。**

```
✓ 「肩背仍是含的，但下巴抬起来了；急了不再变快，改成一字一顿地慢。」
   —— 步态、眼睛、面具都没提，那就是照开场那版演

✗ 把八块又抄一遍、只改了两处
   —— 那就是两个版本的身体，跟"每份服装各写一遍脸"是同一个病
```

页面按阶段复制时会自动把八块带上，所以在这儿重抄纯属重复。

**3. 单段 150 字以内。**
这一段只承担"变了什么"。写到 150 字以上，基本是在把八块重抄一遍。
另有一道总量闸门：**八块 + 所有 `state` 合计 700 字**（见下一节）。

**4. 最多 4 个阶段。**
★ 这不是排版偏好：超过 4 段基本可以断定是在**按场次切**，而不是按转折切。
一个角色真正的转折就那么几个。相邻两段其实是同一个转折的，并掉。

### ★ 什么时候整个留空

**这个角色本人没变**（人不变、处境变 —— 类型片配角多是这样），
或者他是功能性角色（喜剧配角、只推剧情的）—— `arc` 整个不写，**不算漏项**。
开场状态就等于全片状态。

**别给每个角色都硬铺三段。** 不需要弧光的角色套上弧光框架，
是在制造他本来不该有的"变化戏"，反而稀释了档案本该守住的一致性。

### ★ 跟 `crack` 的区别（这条容易混）

`crack` 是**一瞬间**塌掉然后收回去，条件触发，收完还是原来那个人；
`arc[]` 是**一个时期换成另一个时期**，不回弹。

同一个人可以两样都有 —— 而且更常见的写法是：
**`crack` 的触发阈值在后面的阶段里变松了**（原来只在孩子被当面威胁时才塌，
后来任何人提起孩子就塌）。那就写在那个阶段的 `state` 里。

## 五、长度 —— 两道上限

**① 八块合计 400 字以内。** ACTING §6 的目标是 **150–220 词一段流畅散文**，中文按字折算。

★ **这个数不管 `voice` / `superObjective` / `arc`** ——
`voice` 单独贴 audio 字段，`superObjective` 是 canon 不进提示词，`arc` 走下面那道。

**② 八块 + 所有 `arc[].state` 合计 700 字以内**（单段另有 150 字上限）。

★ 为什么另设一道、而不是把 arc 塞进 400 里：页面按阶段复制时给的成品是
**「八块 + 累积到该阶段的所有 `state`」**，这道闸门管的是**那份成品**仍然一眼能读完。
八块自己那 400 是官方 §6 的一段；带上阶段必然更长，因为它同时带着开场那版和后来改掉的部分。
超了通常不是"阶段太多"，是**某一段在重写没变的东西**。

★ **这两条上限的理由跟那三份的 300 字上限不一样，别混。**
那三份是"写多了会压掉图像模型的先验，图反而更差"（实测过）；
这份不喂图像模型，压先验的机制在这儿没有作用点。这份的理由是**可用性**：
档案是给下游**每场改写**用的底本，写成一千字的人物小传，
下游没人会通读一遍再去写一个镜头 —— 那它就等于没有。

## 六、块状存，**不揉成散文**

ACTING §8 rule 5 要求 `One flowing paragraph`，但那说的是**每场改写之后**
进提示词的那一段，**不是存档的形态**。

我们块状存，页面「复制档案」也块状给出，两个理由：

1. **逐块才能上闸门。** ACTING §6 那八条规则每一条都是"必须"
   （每个 tic 带触发、步态取名、至少一条 However-when、softening target 只能一个）——
   存成一整段散文，这八条**一条都上不了闸门**。
   而 `SKILL.md` 维护备注里那条最贵的教训就是：
   **「被声明为必须、却没有闸门」的规则是这个 skill 最危险的一类漏洞**
   （参照物当年就是这么漏成"廊柱下一对石雕瑞兽"的）。
2. **改一处知道改的是哪一块。** 出了问题能审计定位：是 canon 判断错了，
   还是翻译成行为时写歪了。

揉成散文是下游的活。交付时把这句挑明。

## 七、交给下游时必须讲清的三条

这三条不写进档案本身，**也不写进页面、更不写进复制出来的文本**（那是给下游模型的
payload，夹进用法说明会干扰它对内容的理解）—— 它们**只进第 9 步的汇报**，
那是跟人交接的地方。不说，下游默认按最省事的方式处理：

1. **每场改写，核不动。** 每场只按当场的姿态（坐着/跑着/藏着）、动作、
   节拍、时辰重新表达一遍，**绝不与档案矛盾**。
   ★ 但"核"是**这一个阶段的那份**，不是全片唯一那份 —— 见第 3 条。
2. ★ **转移，不删除。** 物理上做不到的行为要**换出口，不是去掉**。
   官方的例子：爱踱步的人被按在沙发上，同样的劲头变成不安的微晃、
   手腕轻抖、撕纸条 —— **能量恒定，出口改变**。
   这条对步态那一块尤其要紧（见上面第二节第 5 条的轮椅例子）。
3. ★★ **有阶段的角色，得先说清这场戏用哪个阶段。**
   阶段是**事实**（剧本里发生了这件事、他因此成了什么样），这份表给到这儿为止；
   **从第几场起按哪个阶段演是导演的判断，这份表不给**。
   页面按阶段各有一个「复制档案·〈那件事〉」，点它拿到的是
   「开场 + 累积到这一段的所有变化」，已经拼好。
   **这个按钮是给导演选卡用的，不是让下游自己挑** —— 它没有依据挑。
   不说这一条，下游会拿着开场那一版一路演到底，弧光就白写了。

## 八、写完自查十一句

1. 换了衣服，这份档案还成立吗？（有没有混进服装）
2. 有没有把底档的脸和体格又写了一遍？
3. 每一条 tic 都带触发条件了吗？（自己数，别信闸门）
4. 步态取名了吗？名字是不是引号包住的？
5. `crack` 有精确的触发条件，还是只写了"偶尔会"？
6. `voice` 四件齐吗？跟 `vocalProfile` 说的是不是一回事？
7. `superObjective` 是**朝着某个人的动词**，还是一个状态？

时间墙那三句（有没有写 `arc` 都要过一遍）：

8. **八块写的是他第一次出场那会儿吗**，还是把几个时期揉成了一个平均值？
   里头有没有"后来 / 渐渐 / 越来越"这种跨时期的话？
   （`posture` 里的"来历"不算 —— 那是前史、过去时）
9. 每个阶段都说清**是哪件事之后**了吗？还是只写了"从第几场起"？
10. **有没有替导演决定从第几场开始切换？** 那句话该删掉 ——
    我们只说"发生了这件事，他因此成了什么样"。
11. 这个角色**真的会变吗**？不会变就别写 `arc` ——
    不需要弧光的角色套上弧光框架，是在制造他本来不该有的变化戏。
