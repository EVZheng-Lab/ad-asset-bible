# 怎么盘点道具

> 场景那份在 `how-to-write.md`，角色那份在 `how-to-write-character.md`。
> 三份共用的纪律（只写需求不写为什么、300 字上限、每一格单独读懂、不写下游的活）
> 写在 `how-to-write.md`，这里只写道具特有的。

---

## 一、★ 只收关键道具 —— 判据是**跨场景**

> **关键道具 = 跨场景出现的道具。** 定情信物、随身兵器、贯穿全片的那封信、
> 被反复传递的钥匙。只在一场戏里用一次的东西，**不进这张表**。

这不是为了省事，跟「一个中式庭院」是同一条理由：

**只有跨场景复用的东西才有漂移风险，才值得建一份资产锁。**
一件道具在第 5 场出现、第 30 场又出现，两次必须是同一件东西 —— 这才需要盘点、
需要参照物、需要首图作为参考资产。而只出现一次的道具，
**列出来反而是在压模型的先验**（跟给场景写 11 件带位置的道具表是同一个错）。

`build.mjs` 会拒绝只覆盖 1 个场次的道具。主资产一场 + 变体一场也算跨场景，合法。

**不确定算不算关键？** 问一句：**这件东西下一次出现时，观众会不会认出它是同一件？**
会 —— 收；不会（一只随手拿的碗）—— 不收，交给图像模型。

**要在汇报里点一句**哪些道具你判断为一次性、没有建档。账目诚实比表长好看重要。

## 二、brief 怎么写

写这四样：

1. **这是什么东西** —— 一把老式黄铜挂锁钥匙、一张巴掌大的黑白合影
2. **料子与做工，用通俗说法** —— 黄铜 / 相纸 / 素银 / 粗陶，
   镂空的菱形柄、边沿摸得圆润发亮。不写材料清单，不写尺寸
   （"比手掌短一截"这种手边比照可以，"长 6.2cm" 不行）
3. **一两处最好认的细节** —— 齿部三个深浅不同的豁口、其中一个明显崩过；
   正面一道斜向折痕。**这就是道具的参照物** —— 道具本身小，
   靠这处细节让两个场次里的它认得出是同一件

   ★ **道具是三类里唯一不走「三步推导」的。** 场景和服装的锚点是**位置参照**
   （给下游一套"站在哪、朝哪"的说法），所以必须从剧本的表演位置推出来。
   道具跟着人走、没有固定位置，它的锚点是**物件自身的一处特征** ——
   所以不问"这场戏在哪儿演"，只问"这件东西身上哪一处最好认"。
   `build.mjs` 因此**从不要求道具 brief 里出现"参照物"这三个字**——服装那边也一样，
   已经改成推荐不强制（见 `how-to-write-character.md` 五之四），只有场景仍是硬性要求。

   但有两条是共通的：**那处细节必须在画面里看得见**，以及
   **优先用痕迹/损耗，别用有规制的纹样与形制**（崩掉的豁口、洗白的折痕、
   摸得发亮的边沿都很稳；"某某纹样""某某形制"要先确认那个年代真有）
4. **有没有间接引用**（见下一节）

不写谁在用它、什么时候用、为什么重要 —— 那些是"为什么有这个需求"。

## 三、★ 状态变体：同一件东西坏了，不是换成另一件

判据还是那一句，换个词：

> **这件东西，在这个变体里还在画面里吗？**

| 变化 | 图生图有共同像素吗 | 判定 |
|---|---|---|
| 同一枚玉佩碎裂 / 烧焦 / 褪色 / 沾血 | 有 —— 那件东西还在画面里 | ✓ 状态变体 |
| 换成一枚**仿制的**玉佩 | **没有** —— 是另一件物 | ✗ 另建一份资产 |

★ **真品 / 赝品调换恰恰是最常见的桥段**，所以这一条比看上去要紧：
赝品是另一件东西（做工略糙、包浆不对，那才是它存在的意义），
跟真品混成一份资产，等于**盘点漏了一件道具**，而且下游没法把"能看出差别"这件事画出来。
另建 `@prop_yupei_fake`，把那几场登记到它名下。

`build.mjs` 在**变体** brief 里拦 `另一件 / 另一枚 / 另一把 / 另一张 / 换一件 /
仿制 / 赝品 / 复制品 / 替代品`。
注意只拦变体 —— **主资产本身就是一件赝品是完全合法的**。

## 四、★★ 间接引用：道具上画着别的资产的形象

这是道具特有、而且最容易被漏掉的一件事。

有些道具的画面里**包含另一份资产的形象**：

| 道具 | 引用了什么 |
|---|---|
| 照片、合影 | 某个**角色**（穿着某一套具体的服装） |
| 油画、肖像、绣像 | 某个角色 |
| 建筑画、舆图、宅邸图 | 某个**场景** |
| 通缉令、画像悬赏 | 某个角色 |

**这类道具不能用文生图。** 凭文字再描述一遍那张脸，出来的必然不是同一个人 ——
这正是"间接引用"最要避免的事。它必须**走参考生图**：
先出被引用那份资产的成图，再以那张图为参考生成这件道具。

所以在 `refs` 里登记引用了谁：

```json
"refs": ["@char_along_gongzhuang", "@loc_warehouse"]
```

页面上会给这件道具打一个蓝框「⚑ 必须走参考生图」，复制文本里也会带上这句话。

### ★ refs 必须指到**服装级或场景级**，不能指到角色底档

```
✗ "refs": ["@char_xiaoming"]              照片上的小明穿的是哪套？下游不知道拿哪张图
✓ "refs": ["@char_xiaoming_xuesheng"]     指到具体那套服装
```

底档只有一张脸，没有衣服。`build.mjs` 会拦下指到底档的写法，并把该角色现有的
服装 tag 列给你挑。引用场景同理 —— 指到具体资产或**具体变体**
（`@loc_shenfu` 还是 `@loc_shenfu_night`？画上是白天那版还是烧过之后那版？）。

### refs 带来生成顺序

有 `refs` 的道具**排在被引用资产之后**出图。汇报时把这条顺序写出来，
不然使用者会先做道具、发现没有参考图可用。

### 什么不算间接引用

- **道具装在另一件道具里**（信放在匣子里）—— 那是两份独立资产，不用 `refs`。
  `build.mjs` 会拦下 `refs` 指向另一件道具的写法
- **道具出现在某个场景里** —— 那是场次关系，`scenes` 字段已经说了。
  `refs` 只用于"这件道具的**画面上**画着那份资产"

## 五、道具与场景的分界：能不能搬得动

| | 归哪 |
|---|---|
| 搬不动、是空间的一部分 —— 地秤、石雕瑞兽、落地烛台 | **场景的参照物**，写在场景 brief 里 |
| 拿得走、会跟着人跨场景 —— 玉佩、钥匙、信、照片 | **道具资产** |

搬不动的东西不会漂移到别的场景去，它的一致性由场景那份资产负责，
不该在道具表里再开一份账。

---

## 六、写完自查四句

1. 这件东西真的跨场景吗？（少于 2 个场次 = 不该在这张表里）
2. 每个状态变体，那件东西还在画面里吗？（仿制品 = 另建资产）
3. 画面上有没有画着别的角色或场景？有 → `refs` 登记了吗？
4. `refs` 指的是服装级 / 场景级，不是角色底档吧？
